## 1. 주문관리 (Ch.4)

### 1-1. 결제완료 (p.118~)

- 주문수집 시 **"결제완료 주문을 주문확인 자동 처리하여 수집하기"** 체크박스 → 신규주문으로 자동 수집.
- 체크하지 않으면 [결제완료] 상태로 수집된 후 [주문확인] 처리 시 [신규주문] 으로 전이.

### 1-2. 주문확인

- 전이: `[결제완료] → [주문확인 처리] → [신규주문]`

### 1-3. 배송지연 전송 (결제완료/신규주문 페이지)

- 결제완료/신규주문 페이지에서 **발송예정일 + 지연사유** 입력하여 채널에 전송.
- **불가 채널 (원문 명시)**: 신세계, 위메프 2.0.
- 이미 쇼핑몰에서 발송예정일이 입력된 주문은 **수정 전송 불가**.

### 1-4. 주문 직접 입력

- 쇼핑몰명 `직접입력`. **수정 불가**, **송장 보내기 불가**.
- 처리 흐름: 수동으로 [배송중]으로 상태 변경.

### 1-5. 주문 동기화

- 동기화 가능 페이지: 결제완료/신규주문/배송관리/출고관리/전체/클레임.
- 송장 직접 처리 시 [배송중] 으로 동기화.
- **클레임 상태는 클레임 페이지에서 확인** (별도 워크플로우 처리 없음 — 채널 자체 처리 필수).

### 1-6. SKU 자동 매칭 규칙

- 매칭 키:
  - 옵션명 있음: `쇼핑몰 상품코드 + 옵션명`
  - 옵션명 없음: `쇼핑몰 상품코드 + 상품명`
- 매칭규칙관리 페이지에서 규칙 CRUD.
- **동일 상품코드 규칙 존재 시 현재 규칙으로 덮어쓰기**.
- 매칭 상태값: `자동 / 수동 / 수정 / 실패`.

### 1-7. 주문 정보 수정 제약

- **수정 가능 상태**: 신규주문, 주문보류, 출고대기, 출고보류.
- **수정 가능 필드**: 상품, 수령자만.
- **수정 불가 필드**: SKU, 택배사.
- **수정 불가 조건**: 취소 또는 운송장 출력된 주문.

### 1-8. 출고지시

- SKU 매칭이 안 된 주문도 출고지시 가능.
- 미등록 상품 → **'기본 배송처' 자동 입력**.
- SKU 매칭된 주문 → SKU 상품의 '배송처' 입력.
- **재고 부족 시 출고불가** (재고관리에서 입고 처리 후 가능).

### 1-9. 발주서 발송 (부가서비스)

- 흐름: 신규주문 → [발주서 발송] → 상태 [출고대기] → 배송처 엑셀 업로드(택배사/운송장번호) → 상태 [운송장출력].
- 이메일 카운트 500건 단위 충전.

## 2. 출고관리 / 발송처리 (Ch.5)

### 2-1. 운송장 자동 출력/입력 (p.137~) [1-1]

- 택배연동 채널: [출력] 클릭 → 송장번호 자동 입력.
- **로젠택배는 발급만**(출력은 별도).
- 편의점 (CU / 이마트24): `[접수하기] → 승인번호 발번 → POSTBOX 접수 → [동기화]로 정상 송장번호 갱신`.

### 2-2. 건별 송장 입력 (p.139) [1-2]

- 주문 [상세] > 택배사 + 운송장번호 직접 기입.

### 2-3. 리스트 택배사 정보 저장 (p.140) [1-3]

- 대상 선택 → 택배사 선택 → 리스트에서 운송장 번호 입력 → [택배사정보 저장].

### 2-4. 주문 EXCEL 다운로드 (p.141) [1-4]

- 택배연동 미사용자 또는 거래처 직배송 시 필수.
- 다운로드 옵션: `[통합 엑셀 다운]` → 양식 선택 → [다운로드].
- **묶음 주문**: 동일한 운송장 번호가 업로드되도록 **동일 묶음 번호** 출력.
- 옵션: "묶음주문별 한 줄로 출력" 선택 가능.
- 묶음 주문으로 업로드하지 않을 주문은 **'주문분할' 처리 후** 엑셀 다운로드.

### 2-5. 송장 EXCEL 업로드 (p.142~143) [1-5]

- 경로: [출고관리] 페이지 상단 [엑셀] > [배송정보 업로드].
- **필수 항목 3개**: `묶음번호, 택배사코드, 운송장번호`.
- 택배사 코드표는 샘플 엑셀의 두 번째 시트에서 확인.
- 필드명 다를 경우 업로드 양식 추가하여 항목명 매핑 가능. 동일하면 "기본양식" 사용.

### 2-6. 주문 출고완료 처리 (p.144) [1-6]

- 대상 상태: `운송장 출력`.
- 동작: [출고완료] 버튼 → 팝업 [확인] → **배송관리 페이지로 주문 이동**.

### 2-7. 주문 출고 보류 (p.145) [1-7]

- 보류 동작: [출고보류] → 보류사유 입력 → 메모에 자동 입력.
- 해제 동작: [출고보류 해제] → **배송정보 입력 여부에 따라 상태 변경** (출고대기 또는 운송장출력으로).

### 2-8. 주문서 인쇄 (p.146) [1-8]

- 양식: 기본양식 / SKU별 패킹리스트 / 추가 양식.
- 동작: 주문 선택 → [주문서인쇄] → 양식 설정 → [인쇄하기].

### 2-9. 주문 합포장 처리 (p.147) [1-9]

- 동작: 2건 이상 선택 → [작업] > [합포장] → 팝업에서 **기본주소지 주문건 1개 체크** → [확인].
- 결과: **체크한 주문 기준으로 묶음 처리**.

### 2-10. 주문 분할 처리 (p.148) [1-10]

- 동작: 묶음주문 선택 → [주문분할] → 팝업 [확인].
- 주문수량 2개 이상이면 **수량 지정하여 여러 개로 분할** 가능.
- **중요 제약 (원문 인용)**: "강제분할 처리한 주문건은 단순히 부분배송을 위한 솔루션 상에서의 강제분할 처리이며 **쇼핑몰상에는 1개의 송장 번호만 전송됩니다.** (부분 발송 가능 쇼핑몰 제외)"

### 2-11. 바코드 출고 매니저 (p.149~150) [1-11]

- 스캔 가능한 상품 바코드: `SKU코드, SKU바코드, 재고관리코드`.
- 스캔 완료 주문 → 자동 [출고완료] 전환.
- [출고완료된 주문] 탭에서 스캔완료 주문 확인 및 운송장 전송.

### 2-12. 상품명 관리 (p.151~153) [1-12]

규칙 필드:
- `적용 사이트`: 전체쇼핑몰 또는 특정 쇼핑몰.
- `적용 범위`: 상품명 / 옵션명 / 추가구매옵션명.
- `검색 문자`: 원본 텍스트에서 찾을 문자.
- `검색 조건`:
  - **부분일치**: 검색문자 포함된 모든 주문.
  - **완전일치**: 정확히 일치하는 주문만.
- `변경방법`:
  - **부분변경**: 검색문자에 해당하는 텍스트만 치환.
  - **전체변경**: 검색문자가 포함된 전체 문구를 치환.
- `변경 문자`: 대체 문자(빈 값 = 삭제).

규칙 적용:
- 선택한 주문 / 전체 주문 중 규칙 적용 대상 선택 → [규칙적용].

### 2-13. 사은품 규칙 설정 (p.154~155) [1-13]

규칙 적용 방식 (2축):
- **자동**: [출고지시] 전환 시 일괄 적용.
- **수동**: 주문 페이지에서 [규칙 사은품 → 전체 분배] 클릭 시 적용.

기본 규칙 필드:
- 사은품 규칙명, 적용 쇼핑몰, 기간(수집일 기준이 가능한 쇼핑몰은 수집일, 그 외 주문일).
- `합계금액` / `합계수량`: **묶음 주문건의 총합** 기준.
- `상품 선택 기준`: 일부 상품에만 적용 또는 제외.

사은품 분배 방법:
- **지정 사은품 분배**: 설정한 상품을 적용.
- **랜덤 사은품 분배**: 사은품 풀에서 랜덤.
- **소진 시 다음 사은품 분배**: 1번 소진 → 2번 사용.

사은품 설정:
- 사은품 상품명: SKU 검색 또는 직접입력. SKU 매칭 시 **재고관리 가능**.
- 분배 수량 옵션:
  - `고정수량 n개`
  - `규칙마다 n개씩` (조건 충족 횟수마다 n개 제공)
  - `주문수량 n배`
  - `제한수량` (총 제공 수량 상한)
- 규칙은 **토글 ON** 인 경우에만 적용.

## 3. 배송관리 (Ch.6)

### 3-1. 쇼핑몰에 송장번호 전송 (p.156~157) [2-1]

- 동작: [배송관리] → '출고완료' 주문 선택 → [운송장 전송] → 쇼핑몰별 주문 선택 → [확인].
- 결과: 정상 전송 시 [배송중] 상태.
- **★ 주의사항 (원문)**:
  - "[출고완료] → [배송중] 으로 한번 변경된 이후에는 이전상태로 변경할 수 없습니다."
  - "[배송중] 상태의 주문건에는 운송장 전송 처리가 불가."
  - **복사주문 / 직접입력 주문**은 운송장 전송 불가 → '마우스 우클릭 > 상태 수동 변경 > 배송중' 처리.

### 3-2. 최종 주문정보 수정 (p.158) [2-2]

- 송장 전송 전에만 가능.
- 엑셀 일괄 수정 시: [엑셀] > [배송정보 업로드] → "이미 배송정보가 입력된 주문도 Excel 정보로 덮어쓰기" 체크박스 활성화 필요.

## 4. 통합 주문 상태 (Ch.7)

### 4-1. 정상 주문 상태 — 13단계 (p.159~161) [3-1]

> 본 절은 OMS StandardOrder 13단계 비교의 **결정적 근거**.

| # | 상태명 | 원문 정의 |
|---|---|---|
| 1 | 결제완료 | 결제완료 페이지에서 확인 가능. 쇼핑몰 신규주문 중 **입금만 확인된** 상태(=주문확인 미처리). 주문 수집창 하단 '주문확인 자동처리'를 **체크하지 않고** 수집한 경우. |
| 2 | 신규주문 | 쇼핑몰에서 주문확인 처리까지 완료된 **배송준비중** 주문. 결제완료에서 주문확인 완료된 주문도 동기화로 신규주문 전이. '주문확인 자동처리' 체크 시 자동 전이. |
| 3 | 주문보류 | 출고지시 전, 준비 지연 또는 즉시 출고 불가 주문을 **사용자가 직접 상태변경**하여 정상 출고건과 구분. |
| 4 | 출고대기 | 출고관리 페이지에서 **아직 운송장번호 입력 안 된** 주문 상태. |
| 5 | 출고보류 | 출고완료 전 잠시 출고 불가 주문을 **사용자가 직접 상태변경**. |
| 6 | 운송장출력 | 출고대기 주문이 **운송장 자동출력 또는 송장파일 업로드**로 택배사/송장번호 등록 완료된 상태. |
| 7 | 출고완료 | 운송장출력 상태에서 [출고완료] 버튼 클릭하여 변경된 상태. **솔루션 내 최종 출고 상태**. 쇼핑몰로 송장전송 가능. |
| 8 | 배송중 | 출고완료 주문의 송장이 쇼핑몰로 전송되어 **쇼핑몰 내 주문에도 송장번호가 입력된** 상태. |
| 9 | 배송완료 | 발송 상품을 **고객이 수취**하였을 때 동기화로 변경. |
| 10 | 구매결정 | 수취된 주문을 **고객이 구매확정**하였을 때 동기화로 변경. |
| 11 | 판매완료 | 판매가 완료된 주문을 **사용자가 직접 상태변경**하여 적용. **주문동기화 시 상태가 변경되지 않음**. |
| 12 | 출고지연 | 솔루션 환경설정의 **출고지연 기준**에 의해 집계되는 주문. |
| 13 | 클레임주문 | 취소, 반품, 교환 등의 주문. |

> ※ 본 13개는 PDF 원문 정의 그대로이며, 출고지연·클레임주문은 **라벨 성격**(다른 상태와 중첩 가능)임을 원문이 명시함.

### 4-2. 클레임 주문 상태 — 11종 (p.162~164) [3-2]

> 클레임 주문은 솔루션에서 **별도 처리하지 않으며**, 취소·반품·교환 요청은 **해당 쇼핑몰에서 직접 처리**한다.

| # | 상태명 | 원문 정의 |
|---|---|---|
| 1 | 취소요청 | **배송 전** 상태의 주문을 고객 또는 판매자가 취소했을 경우 동기화로 변경. |
| 2 | 취소완료 | 취소요청 주문이 쇼핑몰에서 확인 완료 시 동기화로 변경. |
| 3 | 반품요청 | **배송처리 완료 이후** 고객이 반품 신청 시 동기화로 변경. |
| 4 | 반품진행 | 반품요청에 대해 **연동 택배사로 반품접수** 진행한 상태. **롯데택배, 카카오T당일배송** 만 해당. |
| 5 | 반품회수완료 | 반품요청 주문이 쇼핑몰에서 확인 처리 + 회수 처리 완료 시 동기화로 변경. |
| 6 | 반품완료 | 반품회수완료 주문이 쇼핑몰에서 반품완료 처리 시 동기화로 변경. |
| 7 | 교환요청 | 출고된 주문을 고객이 교환 신청 시 동기화로 변경. |
| 8 | 교환진행 | 교환요청에 대해 연동 택배사로 교환접수 진행한 상태. **롯데택배, 카카오T당일배송** 만 해당. |
| 9 | 교환회수완료 | 교환요청 주문이 쇼핑몰에서 확인 처리 + 회수 처리 완료 시 동기화로 변경. |
| 10 | 교환완료 | 쇼핑몰에서 교환 처리 진행 완료 시 동기화로 변경. |
| 11 | 맞교환요청 | 교환요청 중 **맞교환 요청건**. 솔루션 내에서 **마우스 우클릭으로 수동 변경**. |
| 12 | 맞교환완료 | 맞교환요청 처리 완료 시 **수동으로 변경**. |
| 13 | 주문재확인 | 수집된 주문이 쇼핑몰에서 **단일 상태로 조회되지 않고 부분반품/부분취소 등 둘 이상 상태로 조회**될 때 동기화로 변경. **이후 동기화 불가** → 쇼핑몰 확인 후 수동 변경 필요. |

> ※ 4-2의 ‘맞교환요청/맞교환완료/주문재확인’ 3종은 원문이 별도 페이지(p.163~164)에 정리해 둔 항목이며, 4-1의 13단계와 별개 분류.

## 5. 물류배송 주문 조회 (Ch.8)

### 5-1. 물류배송 주문 수집 여부 설정 (p.165) [4-1]

- 쇼핑몰 자체 물류센터를 통해 출고되는 주문 내역의 **수집 여부 설정** 가능.
- **지원 채널**: 옥션/지마켓 스마일배송, 스마트스토어 풀필먼트.
- 활성화 요건 (원문): "옥션, 지마켓, 스마트스토어 쇼핑몰 계정 관리에서 물류배송 주문 수집 항목 '신규주문 수집 및 주문상태 동기화 함' 체크 후 저장".
- 활성화 시 별도 메뉴 **"물류배송 주문 조회"** 생성 → 주문수집·동기화는 해당 메뉴로 분리되고 **자동 생성되는 물류 배송처로 매칭**됨.
- **OMS 영향**: 출고작업용 다른 기능은 제공되지 않음 → 본 카테고리는 OMS 1차 범위 외(별도 모듈 후보).

## 5A. 로그/매칭 관리 — 주문관리 연결 항목 (Ch.9)

### 5A-1. 주문 SKU 매칭 내역 (p.169) [2-1]

- 환경설정 'SKU상품 자동매칭' = 설정 인 경우에만 자동매칭.
- 매칭 상태 4종 (원문 인용): `자동 / 수동 / 수정 / 실패`.
- → §1-6과 정합. OMS `match_rules` + `auto_match_logs` 코드화 근거.

### 5A-2. 상품자동품절 내역 (p.172) [2-4]

- 환경설정 `상품자동품절` 항목이 '설정'으로 되어있어야 자동품절 동작.
- 자동품절 전송 미지원 채널 → 재고 부족 시 상품을 [수정대기] 로 변경.
- 상품 상태 의미 (원문):
  - **품절**: 자동품절 시 **실제 쇼핑몰에서 품절 작업 진행 후** 상태 변경.
  - **대기**: 채널이 옵션 부분 수정 기능을 지원하지 않아 **솔루션 내에서만** 상품/옵션 상태 변경.
- → 재고-listed_products 동기화 시 `channel_capabilities.supportsAutoSoldOut` 플래그 필요.

### 5A-3. 재고할당 규칙 내역 (p.173) [2-5]

- 재고할당 규칙/재고재할당 규칙에 의해 **판매 수량이 변경**된 상품 내역 확인.
- 규칙 자동적용 시 (원문):
  - 상태 [판매중] → 판매 수량 변경 + **[수정대기] 로 변경**.
  - 상태 [품절] / [판매취소] → **판매 수량만 변경**, 상품 상태는 유지.
- → 마스터 재고 → listed_products 동기화 룰 정의 시 본 모델 인용 가능.

## 6. OMS 설계 비교용 핵심 인용 (Q5/Q3 관련)

> 이하는 PDF 원문 인용 + 인용 위치만. 설계 의견은 별도 문서(`field-source.md` §보강 또는 차후 작업)에서 처리.

### 6-1. 묶음/합포장 관련 원문

- "묶음 주문건에는 동일한 운송장 번호가 업로드 될 수 있게 **동일한 묶음 번호가 출력**됩니다." (p.141, 2-4)
- "묶음 주문으로 업로드 하지 않는 주문건은 **'주문분할' 처리 이후** 엑셀을 다운로드 합니다." (p.141)
- 합포장 동작: "팝업창에서 묶음배송처리 할 **기본주소지의 주문건을 체크**한 후 [확인] 버튼 클릭 시 해당 주문기준으로 묶음 처리 완료." (p.147, 2-9)
- 강제분할 제약: "강제분할 처리한 주문건은 단순히 부분배송을 위한 솔루션 상에서의 강제분할 처리이며 **쇼핑몰상에는 1개의 송장 번호만 전송**됩니다. (부분 발송 가능 쇼핑몰 제외)" (p.148, 2-10)

### 6-2. SKU 매칭 관련 원문 (Q4 관련)

- 매칭 키: "**옵션명이 있는 경우** : '쇼핑몰 상품코드 + 옵션명' / **옵션명이 없는 경우** : '쇼핑몰 상품코드 + 상품명'" (p.125, 1-6 영역)
- 매칭 상태: `자동 / 수동 / 수정 / 실패`.
- 출고지시: "SKU 매칭 안한 주문도 가능. 미등록 상품 → '**기본 배송처' 자동입력**. SKU 매칭 시 SKU상품의 '배송처' 입력." (p.131, 2-6 출고지시)
- 재고 부족: "재고 부족 시 출고불가 (재고관리에서 입고 후 가능)."

### 6-3. 운송장 충돌/수정 제약 원문

- "[배송중] 상태의 주문건에는 **운송장 전송 처리가 불가**." (p.157)
- "[출고완료] → [배송중] 으로 한번 변경된 이후에는 **이전상태로 변경할 수 없습니다**." (p.157)
- 정보 수정 가능 상태: "신규주문/주문보류/출고대기/출고보류 상태만 가능." 수정 가능 필드: "**상품/수령자만**. SKU/택배사 수정 불가." (p.128, 2-3)

### 6-4. Q3 관련 — 구매결정/판매완료 전이 원문

- "**구매결정** : 수취된 주문을 고객이 구매확정 하였을 때 **동기화 작업으로 변경**되는 상태입니다." (p.161)
- "**판매완료** : 판매가 완료된 주문에 대해서 **사용자가 직접 상태변경**하여 적용하는 상태로, **주문동기화 시 상태가 변경되지 않습니다**." (p.161)

→ PDF 근거상 판매완료는 **수동 only**이며 자동 전이는 정의되지 않음. (Q3에서 자동 전이를 두려면 OMS 자체 규칙으로 정의 필요.)

### 6-5. Q3 관련 — 클레임 카테고리 원문 비교

PDF가 명시한 클레임 카테고리: `취소요청 / 취소완료 / 반품요청 / 반품진행 / 반품회수완료 / 반품완료 / 교환요청 / 교환진행 / 교환회수완료 / 교환완료 / 맞교환요청 / 맞교환완료 / 주문재확인`.

→ **미수취(고객 미수령)는 PDF 원문에 정의되지 않음.** Q3 후속 결정 시 OMS 별도 정의 여부 확인 필요.

## 7. PDF 미수록 / 보강 필요 항목

본 분석에서 PDF 원문이 다루지 않거나 모호하여 **OMS 별도 정의가 필요한 항목**:

1. **클레임 `미수취`** — PDF 원문 미정의. OMS 추가 여부 결정 필요.
2. **구매결정 → 판매완료 자동 전환** — PDF는 판매완료를 수동 only로 정의. 자동 규칙은 OMS 자체 결정.
3. **운송장 충돌 해소 워크플로우** — PDF는 [배송중] 이후 운송장 변경 불가만 명시. 충돌 시 다음 액션(재발송/취소/이력 기록)은 OMS 정의 필요.
4. **출고지연 기준값의 정량 정의** — PDF는 "환경설정 기준에 의해 집계"만 언급. 일수·시간 단위 디폴트 미명시.
5. **묶음 모델 b (bundleNumber만 공유)와 강제분할의 관계** — PDF는 강제분할 후에도 채널에 1송장만 전송됨을 명시. OMS의 묶음 모델과 정합 필요.

## 8. 본 문서의 사용 방식

- 본 문서는 **결정론적 정리**: PDF 원문에 없는 정보는 추가하지 않으며, OMS 설계 결론도 별도 문서로 분리한다.

- 본 문서를 갱신할 때는 반드시 PDF 페이지 표기(`p.NNN`)와 원문 인용을 함께 기재할 것.
